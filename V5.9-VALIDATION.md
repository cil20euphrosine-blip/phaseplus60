# Phase60Plus V5.9 — branche de test

La V5.9 ajoute les blocs Pectoraux, Ventre plat, Nutrition du soir et Récupération, et conserve le format de stockage `phases60_v5.7` (schéma 7). Les nouveaux relevés sont dans `state.v59`. Aucun historique, programme, charge ou menu existant n'est remplacé au démarrage.

## Utilisation

- Pectoraux : trois jours (lundi, mercredi, vendredi), 45 min maximum, développé incliné 3×8–12, couché 3×8–12, écartés 2×12–15. Semaines 1–2 ou récupération faible : 2/2/1 séries. RIR 2–3, sans échec. La semaine du bloc se choisit manuellement. Ce bloc remplace les exercices pectoraux des cycles historiques ; ne pas additionner les programmes.
- Ventre plat : gainage, dead bug, reverse crunch, Pallof press, deux séries chacun ; suivi des réalisations du jour et tour de taille dans Suivi.
- Nutrition : protéines 130–165 g/j, glucides déjeuner / collation avant séance / dîner après séance, portions de féculents cuites. Le journal saisit les grammes de nutriments, pas le poids des aliments. 3 œufs au petit-déjeuner, sans gluten ni whey, lait de soja. Les anciens menus restent disponibles ; ils ne sont pas convertis automatiquement.
- Récupération : heures réelles, réveils, levers pour uriner, fatigue et ronflements observés ou inconnus. Les repères du contexte ne deviennent jamais des mesures préremplies. Le volume baisse de 30–40 % en cas de nuit fragmentée / fatigue au réveil. L'adaptation est un repère de programmation, pas un diagnostic. Le score historique est plafonné à 69 pour suspendre la hausse de charges des cycles existants.

## Conservation des données

Les clés, IDs et champs inconnus sont conservés. L'import Suivi JSON fusionne les dates et ne remplace pas les valeurs omises ; zéro reste zéro. Il valide tout le lot avant modification. Le JSON de Suivi contient les mesures ; **Profil → Sauvegarder** contient l'état complet, les charges et réglages. Les sauvegardes complètes V5.7 restent restaurables. Une restauration complète remplace l'état par celui de la sauvegarde sélectionnée et garde une copie locale avant restauration. Les autres données du navigateur sont ignorées.

La conservation locale dépend de la même origine et du même navigateur. Tester ailleurs n'apporte pas automatiquement les données du téléphone. Avant une publication future, exporter la sauvegarde complète sur le téléphone ; ne pas effacer les données du site ni changer l'URL.

## Tests

`npm ci`, `npm test`, puis `npx playwright install chromium`.
Lancer `python3 -m http.server 8765` depuis la racine, puis `npm run test:browser`.

Six tests unitaires : import partiel/champs inconnus/zéro, invalidité atomique, anciens champs français, sauvegarde/restauration complète, validation V5.7, restauration avec rollback si erreur de stockage.

Le test navigateur couvre : stockage V5.7, saisies des quatre modules, persistance après recharge, téléchargement et restauration JSON réelle, import de suivi partiel et invalide, écran mobile, manifeste et dimensions des icônes, service worker, recharge hors connexion. Le navigateur Android réel et la boîte de dialogue d'installation sont à vérifier sur l'appareil de l'utilisateur avant publication.

PWA : cache V5.9 incluant les deux nouveaux scripts. Activation lorsque les anciennes fenêtres sont fermées. Suppression limitée aux caches Phase60Plus. Les autres caches et le localStorage ne sont pas supprimés.

La branche `test/v5.9` et la PR brouillon ne déploient rien. La workflow ajoutée ne contient que des tests, avec accès en lecture. Aucune fusion sur main ni activation de déploiement n'est autorisée avant validation de Sylvain.

## Contrôle complémentaire de mise à jour

`npm run test:upgrade` installe réellement le service worker V5.8 issu du commit de base, crée des historiques et 12 semaines de charges, confirme la V5.8 hors connexion, sert ensuite la V5.9 sur la même origine, attend sa mise en attente, ferme l'ancienne fenêtre puis recharge la V5.9 hors connexion. Il contrôle la conservation du profil, des mesures, des validations, des repas, des champs inconnus, des charges, du thème et des caches étrangers à l'application.

## Sur Android avant toute publication

1. Ouvrir l'application actuelle sur le téléphone, dans le navigateur ou la PWA où les données sont présentes.
2. Ouvrir **Profil → Sauvegarde complète → Sauvegarder**. La V5.8 peut produire un fichier nommé `phase60plus_v5_7_backup_...json` : c'est normal. Le bouton **Suivi → Exporter JSON** n'est pas une sauvegarde complète.
3. Vérifier que le fichier JSON est présent dans Téléchargements / Fichiers et a une taille non nulle. Garder une copie. Noter le nombre de mesures et la dernière mesure visible dans Suivi.
4. La V5.9 n'est pas encore servie par l'application en ligne. La PR brouillon est une revue du code, pas une adresse de test PWA. Ne pas changer la branche de GitHub Pages pour essayer la version de test : cela remplacerait la version en ligne.
5. Après validation et publication seulement, conserver la même adresse, fermer toutes les fenêtres de l'app puis la rouvrir avec une connexion réseau. Fermer et rouvrir une seconde fois si la V5.8 reste affichée : la mise à jour peut attendre la fermeture des anciennes fenêtres.
6. Vérifier V5.9 en en-tête, les mesures et charges, puis les quatre modules ; fermer et rouvrir hors connexion pour vérifier la PWA. Ne pas vider les données du site.

Le contrôle et la sauvegarde des données réelles du téléphone exigent une action de Sylvain : aucun accès distant au téléphone n'est disponible dans cette session.
